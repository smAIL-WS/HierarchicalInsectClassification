# The code for Deep learning-based hierarchical insect classification using camera trap imagery

This is the extended reproduction guide, covering the complete experimental workflow: dataset splitting, hyperparameter optimisation, training, and evaluation. For a condensed quick-start (download the published checkpoint and reproduce the paper's evaluation results directly), see [README.md](README.md).

This repository contains the source code used for dataset preprocessing, model training, hyperparameter optimisation, and evaluation. Data artefacts, trained model weights, and metadata required to reproduce the experiments are available separately through Zenodo.

## Associated Resources

### Publication

Mahfoud et al., *Deep learning-based hierarchical insect classification using camera trap imagery* (submitted for publication, 2026). Pre-print is available at https://arxiv.org/abs/2607.28005. 

### GitHub Repository

https://github.com/smAIL-WS/HierarchicalInsectClassification

### Zenodo Archive

Dataset, trained model weights, metadata, hierarchy files, train/validation/test splits, evaluation outputs, and reproducibility artefacts are available via Zenodo:

<https://doi.org/10.5281/zenodo.21765014>

The DuckDB database is required by `split_train_test.py` when generating the train/test partitions used in the study.

## Important Directories

### `data/`

Contains everything downloaded from Zenodo via `download_data.sh`, as well as anything generated locally by `split_train_test.py` (new run folders) and `main.py` / `main_optuna_full.py` (new model checkpoints). This corresponds to `DATA_DIR`, `RUNS_DIR`, and `MODELS_DIR` in `config.py`, which are all the same folder.

Run folders are stored as:

```text
data/YYYY-MM-DD/
```

or, for the published reproduction package:

```text
data/2026-01-19_portable/
```

These folders contain:

- Train/validation/test split files
- Hierarchy definitions
- Node-count information
- Mapping files

The active run is selected using:

```python
RUN_DATE
```

in `config.py`.

Model checkpoints (`.pth` files), whether downloaded from Zenodo or produced locally by training, also live directly in `data/`.

### Dataset Location

The image dataset is stored outside version control and is referenced through:

```python
DATASET_ROOT
```

in `config.py`. When the dataset is fetched via `download_data.sh`, this defaults to `data/IHC_dataset/Crops_clean` (the archive's internal top-level folder is `Crops_clean`, so `config.py` accounts for that nesting).

### Metadata Database

The DuckDB metadata database is referenced through:

```python
DUCKDB_PATH
```

in `config.py`, defaulting to `data/insect_images_public.duckdb`.

### Evaluation Outputs

`analysis_metrics.py` writes its outputs to `analysis_paper/` at the repository root (created automatically if it doesn't exist).

# Setup and Installation

1. Clone the repository:

   ```bash
   git clone https://github.com/smAIL-WS/HierarchicalInsectClassification.git
   cd HierarchicalInsectClassification
   ```

2. Create and activate a Python virtual environment (developed and tested on Python 3.13.2):

   ```bash
   python3.13 -m venv venv
   source venv/bin/activate
   ```

3. Install dependencies:

   ```bash
   pip install -r requirements.txt
   ```

   For exact reproduction of the published environment, install the package versions listed in `environment.txt` instead:

   ```bash
   pip install -r environment.txt
   ```

   `environment.txt` pins CUDA 12.8 builds of PyTorch (e.g. `torch==2.9.1+cu128`), which are only published for 64-bit Linux and require a Linux/x86_64 machine with an NVIDIA GPU (driver supporting CUDA 12.8 or newer). The download is several GB, so make sure you have at least 10 GB of free disk space before installing.

The repository includes two dependency specifications:

- `requirements.txt` provides the packages required to run the project.
- `environment.txt` contains the exact package versions present in the environment used for model training and evaluation.

Users wishing to reproduce the published results as closely as possible should use the versions listed in `environment.txt`.

# Step 1: Obtain Required Data

Download and extract everything from Zenodo into a single `data/` folder at the repository root:

```bash
./download_data.sh
```

This fetches and extracts:

- Insect image dataset (`IHC_dataset/`)
- DuckDB metadata database (`insect_images_public.duckdb`)
- Published split files and hierarchy files (`2026-01-19_portable/`)
- Trained model weights (the published checkpoint)
- Supplementary class list (`ClassificationClasses_IHC.csv`, reference only, not read by the code)

The script is safe to re-run — already-downloaded or already-extracted files are skipped.

`insect_hier_class/config.py` points `DATASET_ROOT`, `DUCKDB_PATH`, and `RUN_DATE`/`RUN_FOLDER` at this `data/` folder by default. If you extract the downloaded files to a different location instead, update these variables in `config.py` accordingly:

```python
DATASET_ROOT = Path("/path/to/IHC_dataset/Crops_clean")
DUCKDB_PATH = Path("/path/to/insect_images_public.duckdb")
```

Published split files and hierarchy files (or your own, generated in Step 2) live inside a folder within `data/`, selected by setting:

```python
RUN_DATE
```

to the corresponding folder name.

## Taxonomy and Naming

The original image dataset uses common-name folder labels such as:

- hoverfly
- true_fruit_fly
- scavenger_fly

For biological consistency, the published experiments, hierarchy files,
and manuscript use the corresponding taxonomic group names where
appropriate (e.g. Syrphidae, Tephritidae, Sepsidae).

The file `data/ClassificationClasses_IHC.csv` documents the complete
hierarchical taxonomy used in the study and provides the correspondence
between dataset labels and the scientific names used in the paper.

# Step 6: Train a Model

## Standard Training

Run, from the repository root:

```bash
python insect_hier_class/main.py --backbone resnet18 --use_pretrained
```

Alternative backbones can be selected using the `--backbone` argument.

For a full list of available backbones, see: `insect_hier_class/config.py`

Checkpoints are saved directly into `data/` as `model_<dataset>_<epochs>_<img_size>_bz<batch>_<backbone>_<lr_adjt>_<timestamp>.pth`.

When a `RUN_DATE` with a validation split (generated with `train_val_test_split = True`) is active, `main.py` automatically trains on the combined train + validation data — matching the procedure described under "Hyperparameter Optimisation" below, where the final selected model is retrained on train+val before evaluation on the held-out test set.

## Hyperparameter Optimisation

Before running, open `insect_hier_class/main_optuna_full.py` and set:

```python
DB_URL = "db/url/here"
```

to a valid Optuna storage URL (e.g. an `sqlite:///` path), so trial results persist across restarts.

Run:

```bash
python insect_hier_class/main_optuna_full.py
```

This requires a `RUN_DATE` generated with `train_val_test_split = True` (Step 2), since the optimisation objectives are computed on the validation split.

Training produces:

- Model checkpoints (`.pth`)
- Epoch summaries
- Per-level metrics
- Validation metrics used for monitoring and hyperparameter optimisation

# Step 7: Evaluate a Trained Model

Run evaluation from the repository root, pointing `--weights_path` at your trained checkpoint under `data/`:

```bash
python insect_hier_class/analysis_metrics.py --weights_path data/model_<your_checkpoint>.pth
```

`--weights_path` defaults to `data/model_Insect_100_96_bz1024_resnet18_OneCycle_2026-01-19_01-09.pth` (the published checkpoint) if omitted.

Additional options:

```bash
python insect_hier_class/analysis_metrics.py \
  --weights_path data/model_<your_checkpoint>.pth \
  --conf_threshold 0.6 \
  --batch_size 1024 \
  --device_id 0
```

- `--conf_threshold` — confidence threshold for hierarchical backoff; higher values exclude less certain predictions (default `0.6`).
- `--batch_size` — evaluation batch size (default `1024`).
- `--device_id` — CUDA device id to use, ignored if CUDA is unavailable (default `"0"`).

This script performs the complete evaluation procedure used for the paper.

The evaluation pipeline includes:

- Hierarchical MAP inference
- Confidence-thresholded hierarchical backoff
- Coverage analysis
- Per-level metrics
- Per-class metrics
- Related-error analysis
- Confusion matrices

All metrics reported in the paper should be generated using this script.

# Notes on Hyperparameter Optimisation

Hyperparameter optimisation uses per-level MCC values computed during training as optimisation objectives.

Final paper metrics are generated using `analysis_metrics.py`, which performs the complete confidence-thresholded hierarchical inference procedure. Consequently, training-time metrics and final evaluation metrics are not expected to be numerically identical.

# Recommended Reproduction Route

For exact reproduction of the published results without re-splitting data or re-running hyperparameter optimisation:

1. Recreate the software environment using the package versions listed in `environment.txt`.

2. Download and extract everything from Zenodo into `data/`:

   ```bash
   ./download_data.sh
   ```

   This fetches the dataset, metadata database, published splits/hierarchy files, and trained checkpoint described in the Repository and Data Availability section, and sets up `data/` so that `config.py`'s defaults (`DATASET_ROOT`, `DUCKDB_PATH`, `RUN_DATE = "2026-01-19_portable"`) work out of the box.

3. Run:

   ```bash
   python insect_hier_class/analysis_metrics.py
   ```

This procedure reproduces the evaluation outputs reported in the paper without requiring dataset re-splitting, hyperparameter optimisation, or model retraining.

Users wishing to reproduce the complete experimental workflow may instead:

1. Generate dataset splits using `split_train_test.py` (Step 2).

2. Train a model using `main.py` or perform hyperparameter optimisation using `main_optuna_full.py` (Step 6).

3. Evaluate the resulting checkpoint using `analysis_metrics.py` (Step 7).

# Paper Reproduction

This section documents the configuration used to generate the results reported in the paper. Unless otherwise stated, experiments were performed using the parameters below.

## Published Experiment Configuration

The train/validation/test split files, trained model weights, and DuckDB metadata database used for the published experiments are available in the accompanying Zenodo archive, fetched via `./download_data.sh` into `data/2026-01-19_portable/` and `data/model_Insect_100_96_bz1024_resnet18_OneCycle_2026-01-19_01-09.pth`.

Using those files is the recommended method for reproducing the published results.

---

## Dataset Sampling

The paper experiments used the following sampling constraints:

```text
Minimum training + validation images per class: 450
Minimum testing images per class:               150

Maximum training images per class:             18,000
Maximum testing images per class:               6,000
```

Where class counts exceeded the maximum limits, random sampling was applied while maintaining within-day and within-device constraints to minimise data leakage.

The exact train/validation/test splits generated for the paper are available through the accompanying Zenodo archive.

---

## Random Seeds and Reproducibility

Experiments were performed using:

```python
DEFAULT_SEED = 42
```

The following random number generators were seeded:

```python
torch.manual_seed(42)
numpy.random.seed(42)
random.seed(42)
```

When CUDA was available:

```python
torch.cuda.manual_seed_all(42)
```

Although seeds were fixed, exact reproducibility may still vary slightly across hardware configurations, CUDA versions, PyTorch versions, and multi-GPU execution environments.

---


### Backbone

The experiments reported in the paper used: 
```bash
python insect_hier_class/main.py --backbone resnet18 --use_pretrained
```
with the architecture-specific configuration defined in `config.py`.

## Training Schedule

Models were trained for:

```python
DEFAULT_NUM_EPOCHS = 100
```

using progressive resizing:

```python
PROGRESSIVE_RESIZE_SCHEDULE = {
    "initial": 96,
    "mid": 112,
    "final": 128,
    "epoch_thresholds": [10, 20]
}
```

corresponding to:

| Epochs | Input Size |
|---------|-----------|
| 0-9 | 96 × 96 |
| 10-19 | 112 × 112 |
| 20-99 | 128 × 128 |

The initial image size was selected based on the modal image size of the source dataset.

---

## Optimiser

Training used Stochastic Gradient Descent (SGD) with:

```python
MOMENTUM = 0.9
WEIGHT_DECAY = 1e-3
```

The final model selected from hyperparameter optimisation used:

```python
LR_BACKBONE = 0.00043
LR_CLASSIFIER = 0.00075
DEFAULT_BATCH_SIZE = 1024
```

Learning-rate scheduling used PyTorch's OneCycleLR policy, with the peak learning rate set to 2.5× the initial learning rate and a warm-up period of 40 epochs.

---

## Model Architecture Hyperparameters

```python
DROPOUT_RATE_CONV = 0.2
DROPOUT_RATE_FC = 0.5
FC_HIDDEN_DIM = 512
```

Dropout was applied to both the convolutional and fully connected components of the network to reduce overfitting.

---

## Loss Function Parameters

The combined loss function consisted of a hierarchical tree loss and hierarchical cross-entropy loss.

Key parameters:

```python
TREE_LOSS_ALPHA = 0.2

TREE_LOSS_BETA = 0.999995

HIERARCHY_WEIGHT = 4.4

ALPHA_START = 1.5
ALPHA_TARGET = 0.3
CE_WARMUP_EPOCHS = 30

ALPHA_LOSS_INVERT = False
```

Cross-entropy weighting was progressively reduced during the first 30 training epochs according to the alpha schedule defined above.

---

## Data Augmentation

Training data augmentation was applied online during training.

### Geometric Augmentation

```python
horizontal_flip = True
vertical_flip = True
rotation_degrees = 15

affine_translate = (0.1, 0.1)
affine_zoom_min = 1.0
affine_zoom_max = 1.2
```

Applied transformations:

- Random horizontal flip
- Random vertical flip
- Random rotation (±15°)
- Random affine translation (up to 10% of image dimensions)
- Random affine zoom (1.0× to 1.2×)

### Photometric Augmentation

```python
brightness = 0.2
contrast = 0.2
saturation = 0.2
hue = 0.1
```

Applied transformations:

- Brightness adjustment
- Contrast adjustment
- Saturation adjustment
- Hue adjustment

Additionally:

```python
gaussian_blur_prob = 0.05
gaussian_kernel_size = 3
```

A Gaussian blur transformation was applied with a probability of 5%.

### Random Erasing

```python
random_erasing_prob = 0.5
random_erasing_scale = (0.02, 0.15)
```

Random erasing was applied with a probability of 50%, removing between 2% and 15% of the image area.

### Normalisation

Training and test images were normalised using dataset-specific statistics:

```python
mean = (0.445995, 0.435061, 0.403322)
std = (0.229014, 0.238985, 0.238830)
```

### Fill Values

The following dataset-specific mean colour values were used when pixels were introduced during geometric transformations:

```python
fill_value = (114, 111, 103)
```

This fill value was used for:

- Rotation padding
- Affine transformation padding
- Random erasing

### Test-Time Processing

No random augmentation was applied during testing.

Test images received:

1. Resize
2. Centre crop
3. Normalisation

using the same dataset-specific mean and standard deviation values listed above.

## Hyperparameter Optimisation

Hyperparameter optimisation was performed using evolutionary multi-objective optimisation (Optuna's NSGA-III sampler) on the training and validation splits.

Optimised parameters:

```text
Backbone learning rate:   0.00005 - 0.01
Classifier learning rate: 0.00001 - 0.01
Batch size:               512 - 4096
```

Objectives:

```text
Maximise MCC at:
- PF4
- PF3
- PF2
- PF1
- Leaf
```

The optimisation therefore used five simultaneous objectives, corresponding to the five hierarchy levels.

An initial optimisation run of 30 trials was performed, followed by additional trials based on available compute resources:

```text
Total trials = 77
```

The final model was selected from the Pareto-optimal solutions using the trial with the highest average validation MCC across all hierarchy levels.

Selected parameters:

```text
Backbone learning rate   = 0.00043
Classifier learning rate = 0.00075
Batch size               = 1024
```

The selected model was retrained using the combined training and validation datasets before final evaluation on the held-out test dataset.
